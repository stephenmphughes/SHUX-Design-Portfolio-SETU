JerseyProducts (Bua Sports)

A small, production-like admin system for GAA jersey products and stock orders, with Rails API, React UI, image uploads via Active Storage, and PostgreSQL.

Project duration: Jan ’25 – Apr ’25

Role: Full-stack (Rails API, React UI, testing, deployment)

Overview

Goal: deliver a lean back-office for managing jersey inventory with reliable CRUD, clean JSON contracts, and deployable infrastructure on EC2. The system ships a Rails (API-only) backend, two clients (primary React; secondary HTML form client), and Active Storage for images, all backed by PostgreSQL.

Stack & Architecture

  • Backend: Ruby on Rails (API-only), namespaced controllers Api::V1, JSON via serializers.
  • Frontend: React client (primary UX), plus a minimal HTML form client for parity.
  • Storage: Active Storage image uploads on Product via has_one_attached :image.
  • DB: PostgreSQL for dev/test/prod.
  • Infra: AWS EC2 (Ubuntu), CORS configured; Rails + client processes.

Design Overview — HTML • CSS • React

A lightweight design system guides structure (HTML semantics), visual language (Bootstrap + custom CSS), and interaction patterns (React pages with shared UI). The admin UI prioritises legibility, quick scanning, and predictable CRUD flows.

HTML (Semantics)
  • Landmarks: <header>, <main>, <nav>, <footer>
  • Accessible forms: labels, required fields, clear error text
  • Meaningful alt text for jersey images
CSS (Architecture)
  • Bootstrap 5.3 utilities + custom card/form styling
  • Consistent typography and color usage
  • Responsive grid; image dimensions set to reduce CLS
React (UI Model)
  • Page-driven UI with shared pieces (Navbar, Footer, List)
  • Local state via useState, fetch for data
  • UI states: loading/empty/error/success across pages

Data Model & Serializers

Entities
  • Product — name, description, price, available, image
  • StockOrder — product_id, quantity, sizes, comment
Serializers
  • ProductSerializer: adds image_url (served via blob paths)
  • StockOrderSerializer: includes product_name
  • Eager loading: includes(:product) on order lists

Core Admin Flows

From viewing products to creating stock orders — the day-to-day admin path in five quick steps.

1. View Products (Dashboard)

Scan cards quickly: image, name, price, availability, and actions.

2. Create Product

Minimal form with validation and image upload preview.

3. Edit Product

Prefilled form fetched via ID; update or delete safely.

4. Create Stock Order

Select a jersey, set quantity/sizes, add optional comment.

5. View Stock Orders

Eager-loaded product names; quick delete to tidy old orders.

  • React (Jest + RTL): Lists render, create/edit flows submit, delete removes items.

Deployment & Ops

  • AWS EC2 (Ubuntu) host; PostgreSQL user/db created via terminal; CORS configured.
  • Troubleshot disk space (logs/cache), server PIDs, and multi-process runs (API, client).
  • React client deployed cleanly; HTML client had comms issues in prod and was deprioritised.
JerseyProducts — EC2 Walkthrough

Reflection

  • Clean JSON via serializers kept the React UI simple and fast.
  • Active Storage blob paths made image URLs reliable across views.
  • Dev/Test vs Deployed: locally both the React and HTML clients worked perfectly. In production, the React client worked, but the HTML client had API communication issues — React writes showed up in the HTML client, but HTML writes didn’t round-trip back to the API.

Outcomes & Next Steps

  • Shipped a stable React admin with image uploads and clear JSON contracts.
  • Stabilise the HTML client in production by aligning base URLs, CORS allowlist, and CSRF handling; use identical JSON:API headers. Add an e2e test: HTML form → API → verify via GET.
  • Hardening: role-based admin auth, upload rate-limits, broader integration + a11y tests.
