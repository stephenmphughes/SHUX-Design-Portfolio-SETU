Friendly Bean

A complete design-to-development brochure website for an Irish mobile coffee cart, designed in Figma and recreated with HTML, CSS, JavaScript and Bootstrap.

Project type: Freelance web design and front-end development

Role: UX/UI design, visual direction, content design and front-end development

Project Overview

From an existing logo to a complete coded website

Friendly Bean is a mobile coffee cart business based in Ireland. The client already had a logo and an established beige-and-brown identity, but needed a website that could explain the business, promote its sustainability values and provide a straightforward route for event enquiries.

I took the project from early ideation through interface design and into a complete front-end build. This included developing the page structure, visual theme, written content, colour palette, product presentation, calls-to-action and overall personality of the website.

The most important part of the project was translating the approved Figma design into a responsive coded website. The aim was to reproduce the design closely while also making sensible decisions about containers, columns, breakpoints, typography, images and interactions in a real browser.

Why this project mattered

This was the first project that allowed me to demonstrate the full relationship between interface design and front-end development. I first designed the complete interface in Figma and then translated it as closely as possible into code, recreating the layout, styling and responsive behaviour in the code editor. In doing so, I carried out both sides of the usual designer–developer workflow: defining the visual experience as the designer and then implementing it as the developer across different browser sizes.

Discovery & Direction

Turning an open client conversation into a clear website structure

The client supplied the existing logo and the core information about the business. I then created an early discovery and direction document that combined targeted questions, proposed website content and visual references. This gave the client something concrete to respond to while helping me define the scope and initial direction of the project.

Early discovery and visual direction

The document began by proposing a strong homepage hero with a clear booking call-to-action, supporting navigation and a headline that would immediately communicate that the Friendly Bean was a mobile coffee business.

It also explored how the business’s main selling points could be communicated visually, including its family-run identity, professional barista service, mobile catering model and approach to sustainability.

These early questions and references helped identify the content still required from the client and created a clearer foundation for the Figma design, page structure and later front-end implementation.

Problem Definition

What the website needed to achieve

The project involved several connected brand, communication, discoverability and booking problems. Each problem influenced the content and interface structure of the finished website.

Brand Consistency

Extend the supplied logo into a website

The existing logo established the beige-and-brown direction. The challenge was to expand this into a complete digital visual system without losing the original brand character.

Landing Page

Explain the service immediately

Visitors needed to understand that Friendly Bean was a mobile coffee cart and be directed towards the main booking action from the beginning of the page.

Sustainability

Make the environmental story memorable

Rainforest Alliance certified coffee and the planting of a tree in Ireland for every case sold were important selling points that needed more emphasis than a standard paragraph.

Discoverability

Support a business without one fixed location

Because the cart moves between events and locations, the website could not rely on a permanent map listing in the same way as a traditional café.

Booking Logistics

Collect useful event information

The enquiry process needed to collect event type, location, preferred date, product requirements and any additional information required to assess the booking.

Product Gallery

Allow the offering to change

The client did not want the website tied to a fixed menu. The product area therefore needed a modular structure that could accommodate future changes.

Interface Design

Designing the website in Figma first

Figma was used to establish the layout, hierarchy, spacing, typography, image treatment and overall visual rhythm before development began.

Designing the complete page first made it possible to understand how each section connected to the next and whether the sustainability story, product information and booking journey felt like one coherent experience.

It also provided an approved visual reference for development. Instead of making major design decisions while coding, I could focus on translating an established interface into a responsive implementation.

Central Project Focus

Translating the Figma design into code

The main development objective was to recreate the approved interface closely while allowing it to behave naturally as a responsive website.

A close translation did not mean fixing every element to one pixel position. It meant preserving the hierarchy, proportions, spacing, typography, colour relationships and interaction intent while adapting the design to different screen sizes.

01

Google Fonts

The selected font families and available weights were imported into the browser so the coded hierarchy remained close to the Figma design.

02

Containers and Grid

Bootstrap containers, rows and columns recreated the major layout relationships while keeping content aligned consistently.

03

CSS Measurements

Repeated spacing, colours, widths, type sizes and component treatments were converted into reusable CSS rules.

04

Responsive Breakpoints

Columns, images and content groups were rearranged at appropriate Bootstrap breakpoints rather than simply shrinking the desktop page.

05

Reusable Components

Product cards, buttons, content sections and form groups were given consistent structures so they could be changed more easily.

06

SVG Assets

Vector graphics remained sharp across screen sizes and could be styled to match the Friendly Bean colour palette.

07

Semantic HTML

Logical sections, headings, labels and alternative text helped support accessibility and search-engine understanding.

08

JavaScript Behaviour

JavaScript was used for interactive behaviour while native HTML controls continued to provide accessible browser functionality.

Design-to-code principle

The browser implementation needed to remain visually faithful to the Figma design without becoming rigid. Components had to respond to content length, viewport width and user interaction while retaining the same overall design language.

Responsive Development

Using Bootstrap as the layout foundation

Bootstrap provided the main container, row, column and breakpoint system. This made it possible to translate the desktop layout into a predictable responsive structure while retaining control through custom CSS.

On larger screens, related text and imagery could sit beside one another. On smaller screens, these sections stacked into a clear single-column order.

Navigation, image sizing, spacing and form controls were also reviewed at multiple widths so the page remained usable between the main Figma frames rather than only matching a small number of fixed screen sizes.

Website Structure

Turning the business requirements into page sections

Each section was designed around a communication, booking or business requirement rather than being included only for visual decoration.

01

Hero and Booking Emphasis

The landing area introduced the mobile coffee-cart service, reflected the existing brand and presented the main booking action before users moved further through the page.

02

Sustainability and Bean-to-Cup Storytelling

The coffee journey was presented visually to connect bean sourcing, preparation, the finished drink and the commitment to planting a tree in Ireland for every case of coffee sold.

03

Flexible Product Gallery

A repeatable product-card structure allowed images, product names and descriptions to be changed without rebuilding the wider page.

04

About and Business Story

The About section introduced the modified horse box, the family-run character of the business and the personal interest behind Friendly Bean.

05

Booking and Enquiry Form

The form collected contact information, event type, location, date, product requirements and an open enquiry message so the client received useful information from the first contact.

Form Design

Supporting real event-booking logistics

A mobile coffee-cart booking requires more information than a standard contact message. Each part of the enquiry form was selected to help the client assess availability, travel, capacity and practical event requirements before responding.

01

Contact Details

Name, email and phone fields give the client reliable ways to follow up and discuss the booking directly.

03

Date and Availability

The event date allows the client to check their calendar immediately before spending time reviewing the rest of the request.

05

Power Requirements

Confirming whether a suitable power source is available helps identify equipment, setup and feasibility requirements in advance.

02

Event Type and County

These fields quickly establish the kind of service required and the likely travel involved in reaching the event.

04

Attendance and Service Time

Expected attendance and required service hours help estimate staffing, stock levels and the volume of drinks that may be needed.

06

Menu and Additional Details

Product choices and an open message field allow the client to understand menu expectations, access needs and any unusual event requirements.

Validation and clarity

Suitable HTML input types, visible labels and required attributes were used to provide appropriate browser controls and reduce incomplete submissions. Users therefore did not have to rely on placeholder text to understand what information was being requested.

SEO and Discoverability

Supporting a mobile business without one permanent location

Because Friendly Bean moves between locations, the website needed to clearly explain the service and the geographical context of the business rather than depending entirely on one permanent map listing.

01

Page Metadata

Descriptive page titles and meta descriptions identified the business and its mobile coffee-cart service.

02

Semantic Structure

Logical headings, sections, links, labels and image alternative text helped search engines and assistive technologies understand the content.

03

Local Service Copy

The written content described the Irish business, its mobile format and the types of events and bookings it could support.

Wider visibility

On-page SEO would need to be supported by consistent business information, local listings, social media activity and online promotion. The website provides the central destination where those channels can direct potential customers.

Outcome and Reflection

A practical bridge between interface design and development

Friendly Bean gave me my first opportunity to manage a brochure website from the initial client discussion to a completed front-end implementation.

The project strengthened my understanding of what happens when a fixed interface leaves Figma and enters a responsive browser. Spacing, typography, images and components have to become flexible systems rather than remain isolated values on individual frames.

It also demonstrated the value of being able to explain visual decisions to a client and then carry those same decisions through to implementation without handing the work to a separate developer.

Project outcome

The finished project represents my position as a designer with front-end development capability: able to establish the visual direction, design the complete interface and build a close, responsive representation of the approved Figma design.
